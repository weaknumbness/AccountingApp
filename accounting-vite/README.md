# AccountingApp — React + TypeScript

Личный учёт товаров, категорий, поступлений и продаж. Сохранён дизайн исходного приложения. Гостевой каталог, отмены и возвраты не включены в этот этап.

## Запуск

Нужен Node.js 22.12+ или 24 LTS.

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local` и заполните **клиентскую конфигурацию** своего существующего Firebase-проекта (Firebase Console → Project settings → Your apps). Если в переданном архиве уже есть `.env.local`, она содержит конфигурацию из вашего исходного архива.

```sh
npm run dev
```

Откройте адрес, напечатанный Vite. Войдите существующим email/паролем Firebase. Новые пользователи могут создать аккаунт кнопкой «Нет аккаунта? Зарегистрироваться». Есть повтор пароля, проверка длины и восстановление пароля. Для проверки без подключения к Firebase нажмите «Открыть деморежим». Демо сохраняется только в localStorage этого браузера, отдельно от реальных данных.

## Firebase: сначала настройка, затем первый вход

1. Сохраните экспорт JSON своей Realtime Database через Firebase Console. Не запускайте старую и новую версии одновременно для реального учёта.
2. Убедитесь, что включён Authentication → Email/Password, аккаунт существует и домен приложения разрешён в Authentication → Settings → Authorized domains. Для локальной разработки проверьте `localhost`.
3. В репозитории есть `database.rules.json`: пример правил личного учёта. Он разрешает владельцу читать свой узел `users/$uid` и записывать **только** `accountingV2`. Старые `cards` и `categories` становятся доступны только для чтения. Сопоставьте с текущими правилами перед публикацией: правила других приложений в проекте нельзя затирать. Если на верхних уровнях раньше был `.read: true` или `.write: true`, дочерний запрет это не отменит.
4. При первом входе приложение копирует старые `users/$uid/cards` и `categories` в `users/$uid/accountingV2` одной транзакцией. Исходные узлы не меняются. Повторный вход не повторяет перенос. Если данные не соответствуют ожидаемой схеме, перенос прерывается с ошибкой, а не пропускает товары.
5. Проверьте число товаров, остатки и общую выручку после перехода. Продолжайте учёт только в новой версии.

Правила в реальную базу из этой среды не публиковались. Вход с вашим аккаунтом и работу с вашей живой базой здесь не проверяли.

## Что реализовано

- Товары: создание/редактирование, поиск, фильтрация, одна или две цены, архив и восстановление. Изменение цены/названия не переписывает прошлые операции.
- Категории: создание/редактирование, поиск, сортировка, показатели. Удаление только пустых категорий. Связи по ID.
- Продажа одной единицы за выбранную цену, блокировка нулевого остатка и повторного клика во время сохранения. Остаток, денежные показатели и запись операции фиксируются одной транзакцией Firebase.
- Поступления: количество и закупочная цена за единицу, журнал поступлений.
- Выручка и валовая прибыль товара, категории и всех товаров; количество единиц и разных проданных наименований.
- Продажи: журнал с ценой, типом продажи, себестоимостью и датой.
- Отчёты: диапазон дат, итоги и самые продаваемые товары.
- Профиль: выгрузка резервной копии v2 в JSON. Это экспорт, импорт/восстановление из интерфейса не реализованы.
- Адаптивная вёрстка, клавиатурное управление формами, Escape, удержание фокуса и reduced motion.

## Правила расчёта

Денежные суммы хранятся целыми копейками. `stockValue` — общая закупочная стоимость оставшихся единиц. Поступление добавляет `quantity × unitCost`. При продаже списывается `round(stockValue / stock)` копеек. Остаток стоимости переносится дальше; последняя продажа списывает его полностью. Это средневзвешенная себестоимость с округлением до копеек.

В старой версии `profit` на самом деле был выручкой. Он переносится в `openingRevenue`, а новые продажи — в `revenue`. Историческую закупку, количество старых продаж и их даты восстановить нельзя. Счётчики продаж и отчёты по датам начинаются с перехода, общая выручка включает старую.

Если стоимость старого остатка неизвестна, прибыль по его продажам не выдумывается: операция получает `cost: null`, интерфейс помечает неполные показатели. Можно указать закупочную цену текущего остатка в редактировании товара; прошлые продажи не изменятся. При смешивании неизвестного остатка с новым стоимость остаётся неизвестной, пока её явно не зададут или остаток не будет продан целиком.

Архивные товары сохраняют финансовую историю. Их остатки исключены из активного ассортимента, выручка остаётся в итогах. Статистика категорий группирует товар по его **текущей** категории; журнал сохраняет также категорию на момент продажи. Валовая прибыль не учитывает транспорт, налоги и другие расходы.

## Почему остальные карточки не обновляются при продаже

`Card` обёрнут в `React.memo`. Обработчики стабильны; `reconcileState` сохраняет ссылки на неизменённые товары и категории между снимками Firebase. Список использует постоянный ID товара как `key`. Счётчики могут обновлять родительский компонент, но соседние карточки пропускают рендер и не проигрывают анимацию заново. Анимация появления привязана к монтированию конкретной карточки.

Тесты расчётов покрывают скидки, нулевые остатки, округления, повтор операции, миграцию, неизвестную себестоимость, архив и сохранение ссылок соседних карточек. ## Публикация

`npm run build` создаёт `dist/`. Содержимое этой папки можно разместить на статическом хостинге, включая GitHub Pages. `base: './'` поддерживает размещение в подпапке. Node.js нужен для сборки, но не посетителям сайта. Клиентская конфигурация Firebase попадёт в JavaScript — доступ к данным защищают Authentication и правила базы.

В будущем гостевой каталог нужно публиковать отдельным набором разрешённых полей. Открывать чтение всего `users` для гостей нельзя.

## Ограничения масштаба

Для личного учёта все v2-данные подписаны одним узлом, а операции используют транзакцию на этом узле. Это обеспечивает согласованность даже между вкладками. При большой истории следует перейти к отдельной серверной операции и пагинации журнала. Офлайн-продажи специально не предлагаются: перед учётом нужна связь с сервером. Если связь пропала после отправки, дождитесь результата и проверьте журнал перед повтором.

## Обновление интерфейса

Карточки товаров и категорий плавно появляются при открытии раздела и добавлении. Продажа не повторяет анимацию уже открытых карточек. Кнопки слегка сжимаются при нажатии. Сообщение о сохранении показывается справа сверху 3,2 секунды, закрывается крестиком; повторное сохранение обновляет таймер. Размер и положение значений выручки/валовой прибыли выровнены. При системном отключении анимаций движение отключается.

Правила Firebase уже исправлены и опубликованы владельцем проекта. Для регистрации повторно менять их не нужно. Файл `database.rules.json` оставлен как эталон: пользователь читает только свой `users/$uid`, а записывает — только свой `accountingV2`. Старые `cards` и `categories` доступны для чтения и переноса.

Для обновления предыдущей версии достаточно заменить папку `src` и перезапустить `npm run dev`. Зависимости не менялись, свою `.env.local` оставьте без изменений. Для хостинга используйте новую сборку `dist` либо пересоберите проект через `npm run build`.


## Регистрация пользователей

На экране входа можно переключиться на регистрацию: email, пароль (минимум 6 символов) и повтор пароля. При успехе Firebase автоматически авторизует нового пользователя, после чего открывается пустой каталог. Товары, категории и операции хранятся в `users/<uid>/accountingV2`. Аккаунты не делят данные; деморежим не импортируется в новый аккаунт. Старые пользователи сохраняют свой прежний UID и данные.

Уже опубликованные правила с проверкой `auth.uid === $uid` подходят для регистрации других пользователей; расширять доступ к базе не нужно. Требуется включённый провайдер Email/Password в Firebase Authentication. Если в проекте настроена более строгая парольная политика, её проверит Firebase и форма покажет ошибку. Реальные новые аккаунты при разработке не создавались: вызов регистрации и ошибки проверены с подменой Firebase, интерфейс — браузерными тестами.

## Удаление из архива и профиль

В «Товары» включите «Архив товаров», откройте меню ⋮ нужной карточки и нажмите «Удалить». Подтвердите удаление в диалоге. Карточка и оставшийся в ней запас удаляются без возможности восстановления. Журнал продаж и поступлений, количество проданного, уникальные проданные наименования, выручка (включая перенесённую из JS-версии) и валовая прибыль сохраняются. Финансовые итоги удалённых товаров хранятся отдельно в `deletedProducts`. После удаления всех товаров категории её можно удалить; общая статистика при этом сохраняется.

Вместо раздела «Настройки» внизу боковой панели находится кнопка с аватаркой и email. Она открывает профиль, где расположены резервное копирование и «Выйти из аккаунта». На узких экранах кнопка доступна под меню.

При обновлении закройте старые вкладки приложения и используйте новую версию на всех устройствах: предыдущая версия не знает о `deletedProducts`. Свой `.env.local` сохраните. Изменения не требуют новых зависимостей или изменений опубликованных правил, соответствующих `database.rules.json`.
