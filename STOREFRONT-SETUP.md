# Витрина для покупателей

Обновление подготовлено на основе `weaknumbness/AccountingApp`, коммит `5bbc52f555a10f8c548f2605d405d77150eece45`.

## Что готово

- Отдельная страница `catalog.html`, без входа и регистрации. Главное приложение учёта остаётся на `index.html`.
- Название витрины, фотографии товаров, категории, обычные цены, наличие без точного количества.
- Поиск, категории, сортировка по цене/названию/наличию и фильтр «Только в наличии».
- Адаптивное оформление в прежней тёмно-синей палитре, плавное появление карточек, поддержка отключения анимаций.
- Отсутствующие товары видны с подписью «Нет в наличии». Архивные и удалённые товары скрыты.
- В профиле владельца: включение/отключение витрины, название, открытие и копирование персональной ссылки.
- По умолчанию публикация выключена. Каждый аккаунт публикует только свой ассортимент.

Это отдельная публичная страница в существующем проекте, поэтому не нужен новый репозиторий, отдельный сервер или Cloud Functions. Корзина, заказ, оплата и цена для друзей не добавлены.

## 1. Обновить код

Сохраните свою рабочую `.env.local`. Архив содержит файлы проекта прямо в корне: `src`, `public`, `package.json`, `catalog.html` и другие. Скопируйте содержимое архива с заменой **в корень локального клона AccountingApp**, рядом с его `.git` и `package.json`. Не создавайте внутри ещё одну папку `accounting-vite` или `AccountingApp`.

Новые зависимости основному приложению не нужны. В терминале корня проекта:

```powershell
npm ci
npm run test
npm run build
npm run dev
```

Откройте адрес, который напишет Vite. Для проверки оформления без Firebase добавьте к адресу `catalog.html?demo=1`. Это явно подписанный пример с вымышленными товарами; он не показывает ваши продажи или остатки.

## 2. Обновить правила Firebase

В Firebase Console откройте **Realtime Database → Rules**, замените правила содержимым обновлённого `database.rules.json` и нажмите **Publish**. Это необходимо один раз перед публикацией витрины.

Правила в архиве основаны на правилах из репозитория. Если после этого вы отдельно меняли правила в консоли, сравните их перед заменой и сохраните нужные ограничения. При разработке живая база не читалась и её настройки не изменялись.

Не устанавливайте `.read: true` на корень или `users`. Открыто только чтение `users/<uid>/accountingV2/publicCatalog` при включённой витрине. Родительские узлы и данные учёта остаются закрыты. Запись разрешена только владельцу. Правила запрещают добавлять в публичные карточки произвольные дополнительные поля.

## 3. Отправить обновление на GitHub

В корне локального клона проверьте `git remote -v`: адрес должен быть `weaknumbness/AccountingApp`. Выполните `git status`, затем добавьте файлы, проверьте список и сделайте коммит:

```powershell
git add src public catalog.html vite.config.ts database.rules.json firebase.emulators.json tests README.md STOREFRONT-SETUP.md
git --no-pager diff --cached --stat
git commit -m "Add public customer catalog"
git push
```

Если работаете в отдельной ветке, объедините её с `main` через Pull Request. Не добавляйте `.env.local`, `node_modules` или `dist` в Git.

Существующий `.github/workflows/deploy.yml` собирает обе страницы в один `dist`, поэтому текущая публикация через GitHub Actions подходит. Секрет `VITE_ENV_FILE` должен содержать прежние рабочие настройки Firebase. Новый секрет или отдельный Firebase-проект для витрины не нужен.

Дождитесь успешной публикации во вкладке Actions. Закройте старые вкладки учётного приложения и откройте обновлённый сайт на всех устройствах: старый клиент не знает о настройках витрины и при сохранении может сбросить публикацию.

## 4. Получить ссылку для покупателей

1. Войдите в свой аккаунт учёта.
2. Нажмите аватарку внизу боковой панели.
3. В разделе «Витрина для покупателей» задайте название.
4. Нажмите «Опубликовать витрину».
5. Нажмите «Открыть витрину» и проверьте её в приватном окне браузера без входа.
6. Скопируйте ссылку и отправляйте покупателям.

Ссылка имеет вид `https://weaknumbness.github.io/AccountingApp/catalog.html?shop=<UID-владельца>`. Копируйте готовую ссылку из профиля: UID не требуется искать или вставлять вручную. Ссылка содержит публичный идентификатор магазина, а не пароль или ключ доступа к частным данным.

При нажатии «Скрыть витрину» публичные данные удаляются, а новые чтения по ссылке запрещаются. Уже просмотренные человеком данные нельзя отозвать из его памяти или сделанных им копий. При потере соединения открытая витрина показывает предупреждение о возможной неактуальности.

## Как происходит синхронизация

Настройки публикации лежат в приватном `accountingV2/storefront`. Функция `projectCatalog` создаёт новый объект исключительно из разрешённых полей. После каждого изменения учёта репозиторий сохраняет и состояние, и эту проекцию в **одной транзакции** на `accountingV2`. Отдельной последующей записи, которая могла бы не успеть после продажи, нет.

Цена на витрине — обычная цена. Продажа по цене для друзей влияет на наличие, но не раскрывает скидку. Категория и название обновляются при редактировании. Статус последнего проданного экземпляра становится «Нет в наличии»; после поступления снова «В наличии». Клиент витрины подписан только на публичный узел через `onValue`, не скачивает приватные данные и не загружает интерфейс администратора.

## Проверки

Основные тесты: `npm run test`. Проверены разрешённые поля, совместимость старой базы, продажа последней единицы, поступление, архивирование, восстановление, удаление, переименование категории и отключение витрины.

Отдельная проверка правил на локальном эмуляторе (Node.js 24, Java 21+, нужен интернет для первой загрузки эмулятора):

```powershell
cd tests/rules
npm install
npm test
```

Используется фиктивный проект `demo-accounting-catalog`, а не ваша живая база. Проверяются публичное чтение, запрет чтения частных узлов, запрет записи гостем/другим пользователем, запрет лишних публичных полей, атомарная продажа/архивирование и отключение публикации.
